## What Went Well

- **Clean incremental layering.** Effects moved `Supply` → `TrueIdentity` → per-seed binding (3.3) → reveal + persistence (3.4) across four stories with no renaming and no rework. Each story's spec deliberately planned the seam for the next.
- **Consistent AD-6 serialization discipline.** `inventory`, `floorItems`, `identifyMap`, and `identifiedByOrdinal` all ride the `RunState` Json root as plain non-transient fields, with `setElementType` only where element erasure required it (`enemies`/`floorItems`). Save/load never regressed across the epic.
- **A real determinism bug caught during development.** Story 3.3 found that `java.util.Random.nextInt(2)` correlates across nearby seeds (would bind every small debug seed identically), and fixed it with `seededRng` (skip-2). Reproduced empirically during code review — a genuine roguelike-integrity save.
- **High-signal reviews.** The multi-agent review correctly converged on real findings and was corrected by empirical probing — e.g. two "High NPE" findings on 3.3 were disproven by a throwaway probe (the no-arg ctor makes `identifyMap` non-null after load).

## Challenges & Recurring Debt

- **No committed test suite (recurring since Epic 1).** Every Epic 3 story used a throwaway `main` harness, deleted after verification. Nothing guards against regressions; each story re-verifies by hand. This was an Epic 1 retro action item and remained open through all of Epic 3.
- **Save-migration fragility surfaced twice.** 3.3 deferred (pre-3.3 save loads a `nanoTime`-seeded, non-deterministic binding) and 3.4 deferred (enum-growth array bounds in `markIdentified`). Same class: a new `RunState` field doesn't handle a pre-existing save deterministically. Accepted under AD-6 (single-slot, no migration), but accumulating.
- **Deviation rationale quality.** 3.3's Deviation 2 reached the correct outcome (no NPE on old saves) via incorrect reasoning ("field is never null because Json invokes the ctor" — it does invoke the no-arg ctor, which builds a throwaway binding). Review caught it. Lesson: verify the *mechanism*, not just that the result happens to be safe.
- **Build quirk still undocumented centrally.** `mvn -o -pl core install` before `exec:java`, and the `exec-maven-plugin:3.1.0:java` harness-run recipe, are re-stated in each story's testing-standards section rather than living in one place (also an open Epic 1 item).
