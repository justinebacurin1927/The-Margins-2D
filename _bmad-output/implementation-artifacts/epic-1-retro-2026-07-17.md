## What Went Well

1. **The architecture spine translated directly into clean code.** AD-3 (single owner), AD-4 (ordered pipeline), AD-5 (single seeded RNG), and AD-6 (serialization root) each mapped to a story and held up under implementation. The upfront planning investment paid off with near-zero rework.
2. **Serialization-root discipline delivered compounding value.** Making entity `map` refs transient and rebuilding the RNG from seed (Story 1.4) not only kept saves clean (map serialized once) but means every future `RunState` field — inventory, fog, Bond, flags — gets persistence for free.
3. **Stories compounded instead of colliding.** 1-1 pre-satisfied most of 1-3; 1-2 removed the screen's RNG ahead of 1-3; 1-4's design made 1-6's `lastStandUsed` persist automatically; 1-6 closed 1-5's "true death" definition cleanly. Good sequencing.
4. **Headless-testability was the core enabler.** Because `RunState`/systems carry no libGDX render types, verification ran fast against `core/target/classes` + jars, catching correctness at the model layer (e.g., proving same-seed reproducibility and no map double-serialization).
5. **Clean, reviewable history.** One story per commit with a descriptive body kept the branch legible.

## Challenges / Friction

1. **Build/verify loop quirk.** Running `-pl desktop exec:java` resolves `core` from `~/.m2`, so code changes require `mvn -pl core install` first; forgetting this caused a stale-artifact launch failure (looked for a deleted `Tree1.png`). Cost a debugging detour.
2. **libGDX Json needed non-obvious accommodations** discovered mid-implementation (not in the story detail): de-`final`ing `RogueTileMap` fields, adding private no-arg constructors, and transient re-wiring. Worked out cleanly but was learn-as-you-go.
3. **`timeout`-based launch can't prove the save-on-quit path.** SIGTERM skips `pause()`/`hide()`, so the file-save path needed a separate `Lwjgl3Files` headless harness to verify. The "just launch it" loop has a blind spot for lifecycle-triggered behavior.
4. **No repeatable test suite.** All verification used throwaway `main` classes compiled ad-hoc. Solid for one-shot proof, but nothing is committed or CI-runnable, so these guarantees won't guard against regressions in Epic 2.
5. **An unrelated art-deletion change rode along uncommitted** the whole epic, requiring careful per-commit path staging to keep it out of story commits. Managed correctly every time, but it's a standing papercut and an accidental-inclusion risk.

## Key Insights

- Investing in the AD spine before coding was the single highest-leverage decision — it made each story a small, well-bounded change.
- "Headless model, render-only screen" is worth protecting as a hard rule; it's what made honest verification cheap.
