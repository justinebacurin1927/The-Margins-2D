## What Went Well

1. **The AD spine held end-to-end, again.** AD-1 (layered core/screen), AD-2 (no libGDX in core), AD-3 (RunState single owner), AD-4 (single acted branch), AD-5 (real-turn ticks), AD-6 (serialization root) each mapped to stories and held under implementation. Story 1.1's continuous-map refactor removed the descend branch entirely, and the single acted path (hunger → thirst → debuffs → temp → clock/weather → detection → companion → enemy → noise → checkLastStand → FOV) is now structurally one branch — the old descend violation is gone, not just patched. The carry item codifying that invariant is closed.

2. **The test net is real now.** Carry #1 (the standing 4-epic brownfield carry) is DONE: a committed JUnit 5 `core/src/test` root with 25+ suites covering round-trip/determinism (`RunStatePersistenceTest`, `SaveMigrationTest`), FlagStore, companion, dialogue/flag (`DialogControllerTest`, `SceneEffectsTest`), inventory/identify (`IdentifyMapTest`, `InventorySelectionTest`) — every harness the old retro asked to port. Tests grew 4.3× and every review's patches landed with a pinning test. The "no committed test net" era is over.

3. **Deferral discipline was the compounding engine.** Each story explicitly carried its out-of-scope items forward and the seams held: 1.2 deferred temperature-balance to 1.6; 1.4 deferred light-tile validation to 1.5/1.6 (closed there); 1.7 deferred the composite-debuff HUD seam + the E-key quick-eat replacement to 1.8 (1.8 delivered `getActiveDebuffLabels` and the deliberate backpack selection). Nothing was silently dropped; `deferred-work.md` grew 9 entries and every one is traceable.

4. **The 3-layer adversarial review earns its keep.** 43 patches, and several were genuine design bugs the unit tests missed: 1.7's top finding (F-01 — Stage-2 Diarrhea's amplified drain re-entered the Well Fed regen block and *healed* a sick player at 3× cadence; blind+edge, two independent probes), 1.8's backward-`[` selection (all three layers), 1.3's deep-clock migration desync, 1.4's daylight-torch FOV downgrade. The "review is not a rubber stamp" finding is the strongest process signal of the epic.

5. **Serialization discipline matured.** The AD-6 conventions (transient fields + field-init defaults, `usePrototypes(false)`, load-time reconcile in `restoreAfterLoad()`) let 8 stories of new persisted state round-trip with zero save-corruption bugs. The AD-8 migration guard landed as tested behavior: `SaveMigrationTest` proves a pre-AD-8 save is rejected by the *absence* of the `saveVersion` key — the stamp AND read-branch shipped together (carry #4 closed; the old "dead saveVersion" failure mode was not repeated).

## Challenges / Friction

1. **Build/verify quirks STILL undocumented** — carry #2, now flagged in TWO retros (2026-07-17 and this one). No `docs/BUILD.md`, no CLAUDE.md section, after 8 stories. The `mvn -o -pl core install` before `exec:java` quirk and the harness recipe keep being rediscovered. This is the one carried item that didn't land. **Re-committed below with a "do it before Epic 2" deadline.**

2. **libGDX Json learn-as-you-go recurred.** De-finaling, no-arg ctors, transient re-wiring were absorbed by story 2, but the *nondeterministic ctor-roll wart* bit twice: 1.3's field-absent save loaded a nanoTime-rolled weather, and the same pattern is the deferred 3.3-identify issue. Root cause: the no-arg `RunState()` ctor (which Json runs) delegates to a seeded ctor that draws gameplay state. The migration rule ("field-absent save inherits ctor-rolled state") needs to be a standing dev-notes rule so every future field either has a deterministic default or a load-time reconcile. **Action item below.**

3. **Silent-tier-change routes were a recurring 1.8 finding cluster.** The notable-event work exposed three separate state-mutation paths that could cross a hunger/thirst/temp tier without announcing it: the amplified drain (DebuffSystem runs after the observation), the mystery-supply USE branch, and temperature recovery (direction-implying lines firing on warming). Each needed an observation or a re-observation. **Lesson for Epic 2:** dialogue effects (Bond, flags, item give/take, disposition) are new mutation paths that must either emit to the log or use capture-before/compare-after — otherwise the same silent-mutation bug class returns. **Action item below.**

4. **Review volume is high (43 patches).** Most were small and unambiguous, but a real cost of the 3-layer rigour. It is paying for itself in bug prevention (see What Went Well #4), so this is "accept the volume" — but the backlog of deferred items should be periodically re-triaged rather than accumulated.

5. **One story's uncommitted state.** Story 1.8 is fully done (205 tests) but not committed — the epic is only "done" in spirit until it lands on `main`. Readiness item.

## Key Insights

- **"Headless model, render-only screen" is the load-bearing rule.** It made honest verification cheap (headless tests over live boot), and the 1.8 HUD/log work proved the screen can stay a pure presentation layer reading core-owned state (the log lives on RunState; the screen never mutates it).
- **Every mutation path is a potential silent event.** The observation discipline (capture-before / compare-after) must be the default for any new state change, not a retrofit done when a review catches it.
- **Deferral discipline compounds.** Explicitly scoped seams + a traceable `deferred-work.md` meant out-of-scope items came back as designed (1.2→1.6→1.8 chains all landed).
- **The test net turned the brownfield core into a guarded core.** 205 tests is the regression net every future epic (dialogue, combat, companions, economy) stands on.
