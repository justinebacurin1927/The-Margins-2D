## Epic summary

## What went well

- **"Model now, UI later" held for all four stories.** The AC-critical logic is fully-tested headless code; bespoke UI was deferred consistently (Quick-Access UI, bag catalog, coin HUD, shop screen). This was the explicit Epic 5 takeaway carried forward — it kept a mechanics-heavy epic bounded and testable.
- **Append-seeded-draws-last (AD-5) was fully internalized** — direct follow-through on Epic 5 action item #3. Every placement drew from a *distinct* seed-derived sub-stream drawn LAST in `generateFloor`: found bags `0x6A6BAD`, currency `0xC0FFEE`, traders `0x77AAD3`. Every pre-existing seed stayed byte-identical; the determinism snapshot/hazard tests needed no placement churn. The clearest "we learned from last epic" win.
- **Deliberate cross-story debt-threading closed a loop.** 6.3 deferred `Supply.copperValue() int→long` with a *named trigger* — "before 6.4 mints plaques" — and 6.4 landed it exactly then, so the Royal Gold Plaque circulates as change without overflow. A deferral with a trigger story that actually got closed on schedule.
- **The scarcity invariant (AD-17) was pinned as tests, not just prose.** "No action mints coin" and "survival never reads the wallet" are guard tests; the buy>base>sell spread is a test. The economy's core constraint is regression-protected.
- **Inline 3-layer review (Blind Hunter / Edge-Case Hunter / Acceptance Auditor) kept catching real bugs** — 16 patches applied across the epic (2+4+4+6), several HIGH severity, all pre-merge.

## Challenges & growth areas

- **The same invariants were re-discovered by review across stories**, rather than applied up front:
  - **Silent item loss / spill discipline (FR-9)** — a review finding in **6.2** (trap-break spill computed loss-by-floor so small stacks survive) *and again* in **6.4** (buy/sell/barter/make-change ignored `tryAdd`'s `BACKPACK_FULL`, so change/proceeds/items could vanish → `receiveOrSpill`/`giveCoin` spill to the floor). Same "route overflow to the floor, never delete" rule, found twice.
  - **RNG-order / no-op-perturbs-the-stream** — **6.2**'s `BagSystem.ready` rolled the trap *before* checking preconditions, so a refused no-op shifted the shared stream (an AD-5 determinism defect, same family as action item #3).
- **"Test-only feature" reachability gap** — **6.1**'s bag expansion was tested but unreachable in-game (no starting bag) until review forced `seedStartingBag`. This is the Epic-4 "screen-reachability" theme resurfacing for a **third epic**: headless-first is right, but a feature isn't done until a reachable hook lands.
- **Documentation drifted from code** — **6.3**'s comments and test names falsely labeled the placement "the three Tier-3 footprints (Deep Cave)" when the code is a geometric east-of-midline gate over all structures. Caught by the Blind Hunter; the substantive fix was doc/test-accuracy, not behavior.
- **Regression I introduced in 6.4** — the new `[T]` trade-open handler shadowed the Story 1.6 `[T]`→craftTorch binding. Caught by review; fixed by gating `[T]` on trader adjacency and falling through otherwise. A reminder that reusing an existing keybind needs a fall-through, not an early return.

## Action items (Epic 6)

1. **Codify the spill / drop-or-leave invariant (FR-9) as a create-story + review checklist item.** Any transaction or capacity change that hands the player an item must route overflow to the floor via `RunState.addFloorItem`, never delete it. Re-found by review in 6.2 and 6.4. Owner: Dev.
2. **Codify the RNG-discipline rule next to the append-last rule:** roll only after preconditions pass; a refused/no-op action must not perturb the seeded stream. Both are AD-5 determinism. Re-found in 6.2. Owner: Dev.
3. **Add a reachability gate to dev-story done-criteria:** a feature is not "done" until it is reachable in the running game, not merely covered by headless tests. The Epic-4 "screen-reachability" → 6.1 `seedStartingBag` recurrence (three epics). Owner: Dev.
4. **Doc-accuracy rule:** comments and test names must describe what the code does, not the story's original framing. The 6.3 "Tier-3 footprints" vs east-gate drift. Owner: Dev.
5. **Final triage of all long-open action items (Epics 3, 5).** The game is systems-complete, so there is no "later epic" to absorb them — close, re-scope, or explicitly defer each. Directly discharges Epic 5 action item #2. Owner: Dev.
6. **Make a scoping decision on the deferred content/UI backlog** (Epic-5 narrative + Epic-6 UI in `deferred-work.md`): open a dedicated Content & Polish epic, or close the backlog as out-of-scope for v1. Owner: Dev/design (Project Lead call).

## Key takeaways

- **Behavioral lessons transfer; bookkeeping lessons rot.** Append-last was applied perfectly; "close stale items / write the guidance down" was ignored for three epics. Force a triage pass, don't rely on the next epic to absorb debt.
- **Codify the invariants the review keeps re-finding.** Spill-to-floor (FR-9) and RNG-after-preconditions are now proven recurring; a checklist beats re-discovery.
- **"Reachable, not just tested" is a done-criterion**, not a review afterthought — three epics of the same lesson.
- **A deferral with a named trigger story works** (6.3→6.4 `copperValue`). A deferral without one ages indefinitely (the open action items). Prefer triggered deferrals.
- **The game is systems-complete.** Six epics delivered; the remaining backlog is content/polish and needs an explicit scoping decision.
